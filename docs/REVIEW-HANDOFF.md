# 交叉审查与现场试用说明

## 审查基线

本次由 gpt-6.1-sol 辅助重写，C#/.NET 8；旧检查器 v1.3.6 与旧提取器 v1.3.2 的可执行文件和源码均保留。新版本暂标识为 **2.0.0-sol 现场试用版**，不冒充旧 1.3.6 原版，也不声称已通过7天稳定性认证。

重点入口：
- `checker/FlexTimeChecker.Core/`：查询、XML、配置、返工、隔离工作进程。
- `checker/FlexTimeChecker/`：查询UI及配置。
- `extractor/Core/`：路径、配置、原子复制/所有权清单、进程隔离和生命周期。
- `extractor/UI/`、`extractor/Service/`、`extractor/Worker/`、`extractor/Tests/`。
- `docs/legacy-contract.md`：旧行为与验收点。

## 不可静默改变的业务规则

Housing直接查询优先；物料查组装关系后查最新点胶；物料使用组装站等待阈值但返工归实际点胶站；拆除严格小于阈值、清胶严格大于阈值；返工按Housing去重且随报文存活，不在午夜重置。

## 必须注意的兼容差异

- 检查器对扫描不完整、异常XML、未来时间和限额超限更保守，不能放行时显示原因。
- 配置只显式导入，旧文件不改；旧返工记录不自动迁移，新程序首次统计重新开始。
- 提取器对目标文件采用Request前缀+来源/内容哈希命名；查询器仍按Request*.xml读取，非依赖旧文件名。
- 提取器仅删除新版自身所有权清单记录且未被改变的过期文件；旧版留下的报文不自动删除，部署前须由现场人员备份/清理，不能把旧数据滞留误当新版自动管理。
- OnlyNew基准跨相同配置重启保留，属于故障恢复修正；配置改变后新会话。
- 查询忙时不无限排队，需等待再扫；两套软件的UI设置、状态文件位置详见各README。
- 每目标目录所有权清单上限20,000条；现场若超过必须先容量评估。不要用无限提高上限来代替负载测试。
- 停止旧提取器及其服务后才能启用新版；新旧互斥机制不兼容。禁止同时写同一目标。
- 采用现有.NET 8.0.22自包含运行库，不宣称最新安全补丁；不应未评估就直接替换生产长期运行程序。

## 试用/回退

解压到新的本机目录；不要覆盖旧版。先用隔离样本导入配置、核对阈值与查码，再由现场授权选择测试目录运行。旧运行目录和配置保持原样，遇异常停止新版，确认其工作进程已停止，再恢复旧版。服务和自启本次不安装。
